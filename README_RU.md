# Telegram Anti-Spam Bot

[English](README.md)

Кроссплатформенный Telegram-бот для модерации групп на Python, aiogram 3 и SQLite. Проект рассчитан на обслуживание одной или нескольких Telegram-групп: проверяет сообщения на спам, верифицирует новых участников, уведомляет администраторов, хранит состояние в SQLite и устанавливается через интерактивный installer для Windows и Linux.

> **Языки:** installer поддерживает русский и английский. Сообщения самого бота и интерфейс администратора сейчас русскоязычные.

## Возможности

- Работа сразу с несколькими группами через `GROUP_IDS`.
- Независимое состояние проверки нового пользователя по `(chat_id, user_id)`.
- До пяти попыток проверки «Я не бот»; одновременно существует только одно актуальное сообщение проверки.
- Таймаут кнопки 7 секунд удаляет только сообщение бота и не удаляет обычное сообщение пользователя/его pending-состояние.
- Антиспам работает на каждом сообщении во время проверки и на отредактированных сообщениях.
- После шестого сообщения без успешной проверки пользователь автоматически ограничивается; чистое шестое сообщение не удаляется.
- Уведомления администраторам о входе/выходе, спаме и автоматических ограничениях.
- Корректная обработка выхода и повторного входа пользователей со статусом `restricted` через Telegram `is_member`.
- Белый список и список пользователей, которых всегда следует считать спамерами.
- Управление стоп-словами через личный чат администратора с ботом.
- Первые три личных сообщения от не-администратора пересылаются администраторам; последующие сообщения этого пользователя игнорируются.
- SQLite, миграции схемы и консистентные резервные копии.
- Секреты хранятся в `.env`, а не в исходном коде.
- RU/EN installer с восстановлением прерванной установки, импортом БД, backup, repair/update и удалением проекта.
- По умолчанию installer показывает только аккуратный прогресс; `--verbose` включает технический вывод.
- Windows: установка текущему пользователю и ручной/foreground запуск.
- Linux: user-install и необязательный systemd user service.
- Linux server mode: отдельный непривилегированный пользователь и hardened systemd service.

## Требования

- Python 3.10 или новее.
- Токен Telegram-бота от BotFather.
- Бот должен быть добавлен во все управляемые группы.
- В группах нужны права на удаление сообщений и ограничение участников.

Версии зависимостей зафиксированы в [`requirements.txt`](requirements.txt).

## Быстрый старт

Склонируйте репозиторий командой, которую GitHub показывает в меню **Code**, и перейдите в каталог проекта.

### Windows

PowerShell:

```powershell
.\install.ps1
```

Или напрямую:

```powershell
py -3 installer.py
```

На Windows установка выполняется для текущего пользователя. Task Scheduler намеренно не используется. После установки можно сразу запустить бота в текущем терминале либо отдельно вывести готовую команду ручного запуска.

### Linux

```bash
./install.sh
```

или:

```bash
python3 installer.py
```

Installer предлагает два режима:

1. **User installation** — для разработки, desktop и простых личных установок. Root не требуется; для автозапуска может использоваться user-level systemd service.
2. **System service installation** — для VPS/сервера. `sudo` используется только для системной подготовки; создаётся отдельный заблокированный пользователь `antispambot`, а сам бот никогда не запускается от root.

Пути server-mode:

```text
Приложение / venv: /opt/telegram-antispam-bot
Конфигурация:      /etc/telegram-antispam-bot/.env
Данные:             /var/lib/telegram-antispam-bot
Service:            /etc/systemd/system/telegram-antispam-bot.service
Пользователь:       antispambot
```

## Что делает installer

Installer умеет:

- создавать и повторно использовать `.venv`;
- устанавливать зафиксированные зависимости;
- запрашивать и локально валидировать настройки;
- при желании проверять Telegram `getMe`, не считая сетевой сбой неверным токеном;
- импортировать старый `state.db` только после проверки SQLite;
- применять миграции БД;
- создавать резервные копии БД;
- обновлять/восстанавливать существующую установку;
- настраивать systemd в Linux;
- безопасно удалять проект с возможностью сохранить данные.

Все вопросы Да/Нет используют цифры (`1 = Да`, `2 = Нет`). Выбранный язык installer сохраняется; если это состояние потеряно или повреждено, используется русский.

### Обычный и подробный вывод

В обычном режиме installer показывает компактный индикатор прогресса и не засоряет терминал выводом `pip`, `systemctl` и других subprocess-команд. Подробности сохраняются в `logs/installer.log` (в Linux server-mode — в каталоге системных данных).

Для диагностики:

```powershell
py -3 installer.py --verbose
```

или:

```bash
python3 installer.py --verbose
```

Недоступность Telegram во время сетевой проверки является предупреждением, а не ошибкой конфигурации. Некорректные локальные значения считаются ошибкой. Если недоступен PyPI, зависимости установить невозможно, но уже пройденные этапы сохраняются для следующего запуска installer.

## Конфигурация

Публичный `.env.example` намеренно не содержит даже вымышленных Telegram ID или токеноподобных значений:

```env
BOT_TOKEN=
GROUP_IDS=
ADMIN_IDS=
WHITE_LIST_IDS=
SPAM_USER_IDS=
DATA_DIR=data
```

`GROUP_IDS` — отрицательные ID групп через запятую. `ADMIN_IDS`, `WHITE_LIST_IDS` и `SPAM_USER_IDS` — ID пользователей через запятую.

Никогда не добавляйте `.env` в Git.

## Как работает проверка нового пользователя

1. Каждое из первых пяти сообщений нового участника проходит антиспам-проверку.
2. Новое сообщение заменяет предыдущее сообщение бота с кнопкой проверки.
3. После таймаута удаляется только сообщение бота; пользователь остаётся pending.
4. Корректное нажатие кнопки сразу завершает проверку.
5. Если пользователь отправляет шестое сообщение, не пройдя проверку, это сообщение всё равно проверяется на спам, после чего пользователь ограничивается.

Состояние разделено по `(chat_id, user_id)` и защищено от конкурентной обработки обновлений одного пользователя в одной группе.

## База данных и backup

Состояние хранится в SQLite. В обычной работе используется WAL, а для резервных копий — штатный SQLite backup mechanism.

Админ-команда `/reserv` создаёт резервную копию БД и не включает `.env`. Installer также умеет импортировать, проверять и резервировать существующую базу при установке и обслуживании.

## Безопасность

- Токен и Telegram ID не хранятся в исходниках.
- `.env`, runtime-БД, логи, `.venv` и backup-файлы исключены через `.gitignore`.
- В Linux server-mode бот работает от отдельного `antispambot` без shell, пароля и sudo.
- Сам бот не должен запускаться от root.
- Код приложения в server-mode отделён от writable runtime-данных.
- ID групп при установке проверяются локально: присутствие бота в группе не требуется для завершения настройки.

Перед публикацией форка отдельно проверьте, что реальные токены, ID, базы и логи не попали ни в текущие файлы, ни в Git history.

## Ручная установка

Если installer не нужен:

```bash
python3 -m venv .venv
python -m pip install -r requirements.txt
```

Скопируйте `.env.example` в `.env`, заполните обязательные значения и запустите из корня проекта:

```bash
python start_bot.py
```

## Первый запуск

1. Каждый пользователь из `ADMIN_IDS` должен один раз открыть бота и отправить `/start`: Telegram-бот не может первым начать личный диалог.
2. Добавьте бота во все группы из `GROUP_IDS`.
3. Выдайте права на удаление сообщений и ограничение участников.
4. Запустите бота через installer, systemd в Linux или `start_bot.py`.
